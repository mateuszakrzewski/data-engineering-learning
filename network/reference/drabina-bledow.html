Drabina błędów

Na którym szczeblu padło połączenie — i czym to sprawdzić.

Reguła 1. Błąd pochodzi z pierwszego szczebla, który nie przeszedł. Wyższych nikt nie próbował.
Reguła 2. Kto mówi? Kod statusu HTTP albo FATAL: = mówi serwer (szczebel 4–5). Wszystko inne = mówi Twój system, do serwera nie dotarłeś (1–3).
Reguła 3. Na szczeblach 4–5 serwer często ukrywa szczegóły przed klientem. Pełny powód jest w logu serwera.
  1. 1

    DNS nazwa → adres IP

    getent hosts nazwa (to, co widzi program; kod 2 = brak) · dig nazwa (sam DNS) · sprawdzaj tam, gdzie działa program — ściąga

  2. 2

    TCP ktoś słucha pod adres:port?

    nc -zv -w 3 host port · pg_isready -h host -p port · lokalnie ss -tlnp

  3. 3

    TLS czy to na pewno on? (ocenia klient)

    curl -v: * Server certificate, * SSL certificate verify ok.

  4. ↓ od tej linii komunikat cytuje serwer ↓
  5. 4

    Auth kim jesteś i czy wolno ci?

    HTTP 401/403 · FATAL: password authentication failed · FATAL: no pg_hba.conf entry

  6. 5

    Aplikacja o co prosisz?

    HTTP 404/5xx · FATAL: database "…" does not exist

Jak czytać linię błędu psql

psql: error: connection to server at "10.0.3.17", port 5432 failed: FATAL:  no pg_hba.conf entry …
└────────────── prefiks: GDZIE próbowałem ─────────────┘        └──── werdykt: CO się stało ────┘
Adres IP i port są w prefiksie zawsze — przy każdym szczeblu. Nic nie mówią o tym, gdzie padło. Patrz tylko na tekst po failed:. Zaczyna się od FATAL: → mówi Postgres (4–5). Nie zaczyna → mówi system (1–3). Słowo refused bez FATAL: to nie odmowa dostępu, tylko „nikogo tu nie ma".

Co zwykle stoi za danym szczeblem w potoku

#Typowa przyczyna
1Literówka w hoście · nazwa wewnętrzna, a jesteś poza VPN · kontener nie widzi firmowego DNS.
2 odmowaUsługa nie działa · zły port · usługa słucha na 127.0.0.1, a pukasz z zewnątrz.
2 ciszaFirewall / security group · zła sieć (VPC, brak trasy) · adres prywatny spoza Twojej sieci.
3Certyfikat wygasł · self-signed w firmie · łączysz się po IP zamiast po nazwie z certyfikatu.
4Złe hasło / wygasły token · brak reguły w pg_hba.conf dla Twojego adresu · brak uprawnień.
5Zła ścieżka lub wersja API · zła nazwa bazy (bez nazwy Postgres bierze nazwę użytkownika) · awaria serwera.
