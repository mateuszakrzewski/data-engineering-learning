Komendy i flagi

Każda litera rozwinięta. Źródło: man na Twojej maszynie.

Złota zasada: nie kopiuj komendy, której flag nie umiesz rozwinąć. man <komenda> · w środku: / szukaj, n następne, q wyjdź.
Jedna flaga bez czytania całości: man ss | grep -A3 -- '-l, --listening' (-- = „koniec flag, dalej tekst do szukania").
Pojęcia kanoniczne (socket, TCP, UDP, daemon, pipe, IPv4/IPv6) mają osobną ściągę: Glosariusz.

dig — pytanie do DNS

DNS lookup utility (pakiet BIND 9); nazwa rozwijana jako Domain Information Groper. Opcje z plusem to query options, z myślnikiem — zwykłe flagi.

OpcjaRozwinięcieEfekt
+shortshortSama odpowiedź, bez ceremonii.
+tracetracePokaż całą drogę od serwerów głównych w dół — widać, gdzie pytanie ginie.
@1.1.1.1—Zapytaj ten serwer, z pominięciem lokalnego. Test: „czy to mój cache kłamie?"
A / AAAAAddressAdres IPv4 / IPv6. A jest domyślne.
CNAMECanonical NameAlias: „ta nazwa to tak naprawdę tamta". Typowe w chmurze.
MXMail eXchangeGdzie iść z pocztą dla tej domeny.
NSName ServerKto jest autorytetem dla tej domeny.
TXTTextDowolny tekst — weryfikacja domeny, SPF.
W wynikuZnaczy
TTL (liczba przy odpowiedzi)Time To Live — sekundy ważności w cache. Powód, dla którego zmiana DNS „nie działa od razu".
INInternet — klasa rekordu. Zawsze IN.
SERVER:Kogo dig faktycznie zapytał. Na Ubuntu zwykle 127.0.0.53#53.
NXDOMAINNon-eXistent domain — nazwa nie istnieje.
SERVFAILSerwer DNS spróbował i poległ. Inny problem niż NXDOMAIN.

getent — zapytaj tak, jak zapyta program

get entries — pobierz wpisy z baz Name Service Switch (/etc/nsswitch.conf). Przechodzi ten sam łańcuch co psql/curl: /etc/hosts, potem DNS. dig pomija /etc/hosts i nsswitch.conf.

ElementZnaczy
getent hosts nazwaBaza hosts: adres dla nazwy. Kod 0 = znaleziono, 2 = nie znaleziono (man getent).
docker exec K getent hosts nazwaTo samo, ale z łańcucha kontenera K. Nazwy z compose istnieją tylko tam.
dig — kod wyjścia0 także przy NXDOMAIN (man dig, RETURN CODES). Jak curl po 401.

ss — socket statistics

Następca netstat. Socket = para adres + port, czyli jeden punkt komunikacji.

FlagaDługaEfekt
-t--tcpGniazda TCP.
-u--udpGniazda UDP (tu żyje DNS).
-l--listeningTylko nasłuchujące. Domyślnie pomijane!
-n--numericNumery portów zamiast nazw usług.
-p--processesKtóry proces trzyma gniazdo (często wymaga sudo).
-a--allNasłuchujące i nawiązane naraz.
Kolumna / zapisZnaczy
LISTENDrzwi otwarte, czekam na połączenia.
ESTABPołączenie nawiązane, rozmowa trwa.
TIME-WAITZamknięte, ale system pilnuje portu jeszcze chwilę. Normalne.
Recv-QPrzy LISTEN: ile połączeń czeka na odebranie. Rosnące = usługa nie nadąża.
Send-QPrzy LISTEN: maksymalna kolejka (backlog). To limit, nie zaległość.
Local Address:PortNajważniejsze. Gdzie naprawdę stoją drzwi. Nie zgaduj — czytaj.
*„Dowolny". 0.0.0.0:* = dowolny adres, dowolny port.
%loAdres żyje na interfejsie lo (loopback). Zapis adres%interfejs.
[::1]Pętla zwrotna IPv6. Nawiasy oddzielają adres od portu (IPv6 ma własne dwukropki).

nc — netcat

cat dla sieci. Domyślnie TCP.

FlagaRozwinięcieEfekt
-zzero danychTylko sprawdź, czy port odpowiada — nie wysyłaj nic.
-vverboseKonieczne — bez niego -z milczy.
-w NwaitPoddaj się po N sekundach. Lekarstwo na zawieszenie.
-uUDPPukaj po UDP.
-llistenSam zostań serwerem — do testów „czy firewall mnie przepuści".
 
nc -zv -w 3 db.firma.pl 5432    # standardowy test portu bazy

pg_isready — czy PostgreSQL gotowy?

Flaga / kodRozwinięcieZnaczy
-h--hostAdres serwera.
-p--portPort (domyślnie 5432). Uwaga: w ss -p = processes.
kod 0—Przyjmuje połączenia.
kod 1—Odrzuca (np. w trakcie startu).
kod 2—Brak odpowiedzi — szczebel TCP.
kod 3—Nie próbowano (złe parametry).
 
pg_isready -h 127.0.0.1 -p 55432 ; echo "kod: $?"   # bez hasła; sprawdza TCP + czy to Postgres

Algorytm: coś nie działa

#PytanieKomendaJeśli źle
1Czy nazwa rozwiązuje się na IP?dig +short <host>Problem DNS: literówka, zła sieć, brak rekordu.
2Czy port odpowiada?nc -zv -w 3 <host> <port>refused → usługa/port. timeout → firewall/droga.
3(lokalnie) Na jakim adresie to stoi?ss -tlnp127.0.0.1 zamiast 0.0.0.0 → niewidoczne z zewnątrz.
4Czy rozmowa się udaje?curl -v <url>Patrz, jak daleko doszły gwiazdki.
Nie zaczynaj od końca. Odmowa (refused, natychmiast) = problem usługi. Cisza (timeout) = problem drogi. Nigdy nie szukaj firewalla przy refused i nigdy nie restartuj usługi przy timeoucie.
